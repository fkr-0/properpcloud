### Typed server-catalog failures

Commit `bcc90a7728fc3cf8ef20efa5ededd53fc580f3a6` adds an explicit server-catalog request failure boundary:

- HTTP 401: authentication failure.
- HTTP 403: permission failure.
- HTTP 404/410: catalog resource unavailable.
- HTTP 429: rate limited.
- Other 4xx: rejected client request.
- 5xx/other non-success: server unavailable.
- Malformed successful JSON: invalid/unsupported server response.

Android now turns these failure kinds into actionable, redacted user messages instead of collapsing every HTTP failure into a generic `IOException` message. Provider response bodies and numeric status details are not exposed in presentation text.

Playback semantics remain conservative: only server stream 404/410 is terminal item-unavailable evidence; authentication, throttling, connectivity, invalid-response, and server failures remain transient and do not justify destructive queue skipping.
